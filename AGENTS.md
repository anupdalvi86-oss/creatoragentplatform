# Agent handoff for Creator Agent Platform

Read `README.md` and `docs/HERMES_HANDOFF.md` first. Then read `docs/AGENT_CATALOG.md`, `docs/ARCHITECTURE.md`, `docs/AGENT_RUNTIME.md`, `docs/DATA_MODEL.md`, `docs/CREATOR_SCOUT.md`, and `docs/DEPLOYMENT.md` before changing agent behavior or infrastructure. The checked-in code and migrations are authoritative when a document is stale; report discrepancies and update the docs in the same change.

This is a multi-tenant cooking and fitness PWA platform and Cloudflare Worker backed by D1. Hermes is an external **engineering assistant**, not the deployed consumer runtime. A creator-configured cooking agent, Creator Scout, and the specialist task dispatcher with Queue/Workflow bindings exist; provider-dependent handlers can still report integration requirements. Never claim a catalog entry's external provider is live merely because it appears in documentation or in the `agents` table.

Build the shared task/run foundation first, then advance independent content, consumer, engineering and operations tracks in parallel where separate branches/worktrees and integration capacity allow. Milestones are integration/release checkpoints, not a mandate to build one role at a time. Before edits, inspect the branch, worktree, latest commit, migrations, existing tests, and requested scope. Preserve unrelated user changes (including any untracked files). Use feature branches and additive D1 migrations; coordinate schema and API ownership across tracks. Keep creator isolation and rights checks on every read/write. Internal read-only reports and existing customer-facing responses need no special draft gate. Keep new content/transcripts out of consumer retrieval until authorized and reviewed; don't let an LLM approve payments, public publishing, source rights, or production deployment.

The product owner confirmed on 2026-09-25 that source-hosted demonstration videos from `harshvishu/free-exercise-db-with-videos` may be used in this fitness app. Treat that app-specific playback as authorized under `docs/FITNESS_MEDIA_POLICY.md`; do not extend it to bulk rehosting, other media sources, or YouTube transcripts. Creator programs and challenges still require human review before publication.

Run `npm run typecheck`, `npm test`, `npm run lint`, and `npm run build` for code changes; `build` is a Wrangler **dry run**, not a deployment. Report tests and any skipped checks accurately. Do not push, apply remote migrations, alter Railway/Cloudflare secrets, or deploy without explicit owner approval for that action. Never print or commit credentials. The model credentials for Hermes/Railway and for this Cloudflare Worker are separate.

The excluded roles are listed in `docs/AGENT_CATALOG.md`. Do not implement them under this initiative. Do not add new agents for commercial optimization or automatic release authority.
